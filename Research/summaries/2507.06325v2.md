# Optimization of Fractal Image Compression
- **Authors / year / venue:** Nastaran Pourshab and Mohsen Bagheritabar; 2025; arXiv:2507.06325v2 (preprint).
- **Core method:** Modifies an existing open-source block-based fractal encoder to reduce encoding work and stored transform bits. Box-counting dimensions select which range blocks retain transformations.
## Key techniques
- Vectorize domain-block averaging; optionally add Gaussian smoothing.
- Reduce contrast quantization from 8 to 4 bits, using the paper's stated bound `|α| < 2`.
- Remove reflections and restrict rotations from four angles to 0° and 90°.
- Box counting uses a pixel-mean threshold T1 and a fractal-dimension threshold T2 to omit range-block transforms.
## Reported results
- Tests: 256×256 Monkey and 512×512 Einstein images on Kaggle; primary comparisons use 32×32 domains and 16×16 ranges.
- Vectorization: Monkey encoding 12.95→9.70 s; Einstein 157.025→124.84 s.
- Fewer geometric transforms: Monkey 3.033 s, CR 89.04, RMSE 12.76; Einstein 34.061 s, CR 81.92, RMSE 16.23.
- Combined transform reduction, contrast quantization, and box counting: Monkey CR 81.92→118.43, time 12.95→3.562 s, RMSE 12.86→17.27.
- Combined Einstein: CR 75.85→104.90, time 153.00→47.91 s (Table 10 baseline), RMSE 15.22→19.27.
- No PSNR or SSIM reported; greater block omission substantially worsens RMSE.
## Implementation assessment
- **Worth trying:** Vectorization and configurable transform subsets are simple, independent encoder optimizations.
- **Cautions:** Combined gains sacrifice reconstruction quality; only two test images and image-specific thresholds/filter settings are evaluated.
- CR is calculated from assumed transform bit allocations, not a demonstrated complete serialized bitstream; account for omitted-block locations and reconstruction rules.
- Verify contrast quantization/convergence and omitted-block decoding before implementation; these details are insufficiently specified for a robust codec.
